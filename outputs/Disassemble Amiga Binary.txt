Yes — this has turned out quite well. The binary is a raw, self-relocating 68000 image rather than a normal Amiga HUNK executable. The bootstrap relocates the payload from file offset `$007C` to runtime `$EE82`, giving a consistent `runtime = file offset + $EE06` mapping. The PC-relative calculation here is consistent with the 68000 using the address of the extension word as the PC base. ([thedigitalcatonline.com](https://www.thedigitalcatonline.com/blog/2019/03/04/motorola-68000-addressing-modes/?utm_source=chatgpt.com))

More importantly, I’ve positively identified two substantial graphics areas:

- `$1DA90–$1F9CF`: a 160×100, 16-colour image, stored as four contiguous bitplanes. The following 32 bytes at `$1F9D0` are its palette. The 68000 code itself confirms this by copying exactly `4 × 100 × 20 = 8000` bytes and then immediately writing the following 16 colours to `$DFF180`. This renders as the Cybernoid cover/title artwork.
- `$1FC68–$3DC67`: exactly `$1E000` bytes, resolving perfectly into 960 × 16×16 tiles at `$80` bytes each. They are 4-bitplane graphics with each scanline stored as plane-0 word, plane-1 word, plane-2 word, plane-3 word. The next address, `$3DC68`, is explicitly treated by the code as workspace rather than graphics, so the boundary is particularly convincing.
- I also found two game palette tables at `$3FFD0` and `$3FFF0`; I’ve rendered the tile block under both rather than guessing which is associated with which game state/level.
- There are additional processed/packed-looking areas around `$62436/$624B6` which I have not yet called graphics because the startup code manipulates them before use. Those are a good next target.
